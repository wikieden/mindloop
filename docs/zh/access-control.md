# 屋主访问控制 —— 运行时策略覆写（T5-10）

关闭 TASK-FAMILIES §1.2 挂起的"屋主访问控制规范"：区域策略与权限**运行时**如何改、谁能改。

## 规则

1. **只有一扇门。** 运行时覆写唯一入口是 `Phylax.replace_policy(new_policy,
   actor_role=...)` —— 整个 `Policy` 原子替换。不提供逐字段修改 API；策略作为
   整体被审阅、被替换（与 D4 §9 "整计划阻断"同理）。
2. **仅屋主级。** `actor_role` 必须是 `"adult"`；否则抛 `PermissionError`，
   在位策略不动（响亮拒绝 + 日志）。四角色模型（adult/child/guest/stranger）
   不变 —— "屋主"就是能物理/账号接触机器人控制台的成年人。
3. **不可自我提升（D-O）。** 打断话语、Clarifier 回答、LLM 计划没有任何代码路径
   能到达 `replace_policy` —— 覆写属控制台/API 领地，绝不属对话。访客说不开这扇门，
   机器人自己也说不开。
4. **仅任务边界生效。** 覆写在任务之间应用（gate 逐轮重读）；在途计划按其
   审查时的策略跑完。
5. **离线只紧不松。** P7.4 `offline_policy` 换入按约定只收紧；推荐填
   `conservative_policy()`。离线状态下屋主覆写同样要求 adult 操作者。

## 这不是什么

- 不是身份认证 —— *谁算 adult* 是设备包的问题（声纹、App 登录、物理按键）。
  本规范从身份结束处开始。
- 不是逐句权限弹窗 —— 在位策略是数据（`Policy`），按部署编写，改得少、改得慎重。
