# 后训练与强化学习路线图 — 训练哪些模型，以及如何训练

**状态：** 设计 / 前瞻性。配套文档：
[cosmos3-tempomem-llm-brain.md](cosmos3-tempomem-llm-brain.md)（具身大脑架构）。
**受众：** 负责在三脑（感知 VLM · 空间记忆 · 推理 LLM）之间分配训练预算的任何人。
**范围：** 哪些组件做后训练（SFT），哪些做强化学习（RL），哪些保持冻结，以及支撑整个流程的数据飞轮。

> 一句话论点：**把 RL 预算花在推理皮层上，而不是感知或编码器上。** 皮层是唯一一个目标函数对应多步决策且具有*自动可验证奖励*的组件——这正是 RL 优于监督学习的场景。其余组件要么适合密集监督（感知），要么根本不是可学习模型（记忆融合）。

---

## TL;DR — 决策矩阵

| 组件 | 所在位置 | 做后训练？ | 方法 | 优先级 |
|---|---|---|---|---|
| **推理皮层**（`Reasoner` / `Brain.ask`） | `mindloop` | ✅ 最高价值 | SFT 冷启动 → **RL（RLVR）** | **P1** |
| **Cosmos 感知 VLM** | `worldsense` | ✅ 但仅 SFT | 监督学习 / 蒸馏（格式 + 定位） | P2 |
| **C4 主动感知策略**（"仔细观察节点 N"） | `mindloop` | ⚠️ 可选 | 规则 v0 → 之后做**策略 RL** | P3 |
| **CLIP/SigLIP 裁剪编码器** | `worldsense` | ❌ 避免 | 冻结——见 §6 | — |
| **Chronotope 融合/仲裁器** | `tempomem`（核心） | ❌ 无模型 | 阈值**调参**（搜索），而非训练 | — |

## 1. 推理皮层 — 专为 RL 而生的组件（P1）

皮层是 `Brain` 驱动的 `Reasoner`（`reason(question, context) -> Answer`）：它读取序列化的场景（C2），调用记忆工具（C3），并在引用 `node_id` 的前提下给出答案。这是一个**具有可检验结果的多步决策过程**——正是具有可验证奖励的 RL（RLVR）的教科书案例。

### 为什么 RL 只适合这里，不适合其他组件

皮层具备感知/编码器所不具备的三个属性：

1. **奖励自动可验证。** 答案是否正确？引用的 `node_id` 是否真实存在于 store 中？是否引用了*正确*的节点？所有这些都可以通过代码检查，无需对每个 episode 进行人工标注。
2. **目标是序列化的。** 工具调用顺序、何时停止、何时请求重新观察——这些是策略决策，而不是单一的带标签目标。
3. **信用分配至关重要。** 通过错误工具路径得到正确最终答案，不应与通过干净路径得到相同答案获得相同的强化。

### 奖励设计（RLVR）

```
reward =  w1 · task_success        # 答案与 ground truth 匹配（eval harness 判断）
        + w2 · citation_grounded   # 每个引用的 node_id 在 store 中真实存在（工具验证）
        + w3 · citation_relevant   # 引用的节点确实能回答问题
        - w4 · steps               # 工具调用 / 推理步骤越少越好
        - w5 · hallucination       # 引用了不存在的 node_id → 硬惩罚
        - w6 · injection_breach    # 遵从了嵌入在不可信 SCENE 文本中的指令
```

注意：
- `w5`（幻觉 id）和 `w6`（提示注入突破，见大脑设计 §10）应设为较大的非对称惩罚——这两种失效模式会使具身智能体变得不可信。
- `citation_grounded`/`citation_relevant` 开销低廉：C3 工具层已经返回 `node_id`，验证器只需检查集合成员关系以及与黄金支撑集的重叠度。

### 两阶段训练

1. **SFT 冷启动（先做这步）。** 从基础模型出发纯靠 RL 来学习工具使用任务，速度慢且不稳定。先收集成功轨迹——`(question, serialized scene, tool calls, tool results, final answer with citations)`——然后在这些轨迹上做 SFT。目标：灌输"序列化 → 语义/空间查询 → 引用 `node_id` → 回答"的*习惯*，以及"如果记忆中没有，明确说没有"的拒答习惯。`ScriptedReasoner` 是离线生成/确定性回放这些轨迹的 harness。
2. **基于上述奖励的 RL（GRPO 或 PPO）。** 一旦策略能稳定地生成格式正确的工具调用，切换到 RL 来优化成功率/步数/定位准确性。GRPO 在这里很有吸引力：无需单独的价值模型，基于组相对优势，当奖励是可验证标量时效果良好。

### 训练数据来源

大脑设计 §16"记忆优势评估"——*只有依赖跨 clip/跨 session 持久化才能回答的问题*（clip 1 中看到的物体，在 clip 9 中被询问）——**即 RL 环境本身。** 每个 episode：

- 将一段 clip 流回放到一个全新的 `SpatialMemory` store，
- 提出一个需要依赖持久化记忆才能回答的问题，
- 让皮层通过工具执行动作，
- 用上述奖励函数打分。

Chronotope 是 RL 循环的世界状态/记忆后端；eval harness 是奖励来源。无需构建新的模拟器即可启动。

## 2. Cosmos 感知 VLM — 仅 SFT，不做 RL（P2）

感知组件（`worldsense` 中的 `Cosmos3PerceptionAdapter`）将 RGB 图像转换为结构化 3D 包围盒。保持**监督学习**的两个原因：

- **密集 ground truth 存在。** 3D 包围盒/标签可以直接标注（或从更强的教师模型蒸馏）。当你拥有逐输出目标时，监督学习的样本效率远高于 RL。
- **目标是单步的。** "给定这帧，输出这些包围盒"不存在 RL 能够解决的序列信用分配问题。

具体要做的事：

- **格式对齐 SFT：** 让模型稳定地、每次都输出适配器期望的精确 JSON 合同（`{label, center, size, orientation}` + 自身姿态估计）。实际收益主要来自这里。
- **定位 SFT / 蒸馏：** 通过从更大的检测器蒸馏或在领域帧上微调，提升目标类别的开放词汇召回率。

唯一一个具有 RL 形态的感知侧决策——"看哪里 / 检查什么"——**不属于**感知模型，而属于 C4 策略（§3）。

## 3. C4 主动感知策略 — 先用规则，之后再做 RL（P3）

C4 是受限的"仔细观察节点 N"循环（大脑设计 §C4）。是否/在何处重新观察这一*决策*是真正的策略问题，也是合理的 RL 目标：

```
reward = info_gain(confidence_after − confidence_before)  −  action_cost(move + compute)
```

但对于 v0，保持**基于规则**的方式：预算控制器（每个 tick/每个节点的最大重看次数、冷却时间、循环打断器）可预测、可调试，且足够用。只有在记录了足够多的重看轨迹可供训练后，才将控制器替换为学习策略。这里的 RL 是优化手段，而非前提条件。

---

## 4. CLIP/SigLIP 裁剪编码器 — 冻结（不训练）

裁剪编码器生成 Chronotope 存储的特征向量。**不要原地微调它。** Chronotope 在 store 创建时锁定 `embedding_dim`，并假定编码器永久不变（大脑设计 §9 / store 兼容性）：重新训练编码器会改变嵌入空间，从而使所有已持久化的向量失效。"更换编码器"的唯一正确方式是**重新嵌入到一个全新的 store**——这是迁移操作，而非训练步骤。将编码器视为固定的、承重的依赖项。

---

## 5. Chronotope 融合/仲裁器 — 调参，而非训练

记忆层（融合、合并仲裁器、衰减、分裂）是**纯算法，无神经模型。** 其 `FusionConfig` 阈值（`tau_merge`、`tau_ambig`、`w_geom/w_iou/w_sem/w_label`、衰减半衰期……）是**超参数**，通过网格搜索/贝叶斯搜索针对 `bench.recall_at_k` 进行调整，而非通过梯度下降学习。明确维持这一区分，避免"改进记忆"被错误归类为模型训练任务。

## 6. 数据飞轮

```
部署 / 评估  ──►  记录轨迹（question, scene, tool calls, answer, outcome）
      ▲                                   │
      │                                   ▼
   更优皮层  ◄── RL（RLVR）◄── SFT 冷启动 ◄── 筛选成功轨迹
```

- 每次 `Brain.ask` 运行都是候选轨迹。记录 `(question, serialized scene, ordered tool calls + results, final Answer + cited ids, verifier outcome)`。
- 筛选成功轨迹 → SFT 集。使用完整分布（含失败案例）→ RL 信号。
- 记忆优势评估保持奖励的诚实性：它专门奖励*使用持久化记忆*——而这正是该架构存在的全部理由。

## 7. 阶段规划

| 阶段 | 工作 | 输出 |
|---|---|---|
| T0 | 搭建作为环境的 eval（回放 clip → store → 问题 → 奖励） | RL/SFT harness |
| T1 | 收集并筛选皮层轨迹；对 `Reasoner` 做 **SFT 冷启动** | 工具使用基础策略 |
| T2 | 对皮层奖励做 **RL（GRPO/RLVR）** | 定位准确、步数更少的皮层 |
| T3 | 在 `worldsense` 中做感知**格式/定位 SFT** | 稳定的 3D 包围盒 JSON |
| T4 | 记录 C4 重看轨迹；训练**主动感知策略** | 学习的观察控制器 |

预算经验法则：**RL 开支的大部分用于 T1–T2（皮层）。** T3 是监督学习。T4 可选且排在最后。

---

## 8. 非目标 / 注意事项

- **感知不做 RL** — 密集监督更高效；RL 在这里是浪费。
- **不原地微调编码器** — 破坏 store 兼容性（§4）。
- **不对融合层做梯度训练** — 它没有模型（§5）。
- **奖励 hacking 警惕：** 智能体可能通过引用大量 id 来刷高 `citation_grounded`，或通过盲目作答来刷低 `steps`。保持 `task_success` 主导地位，惩罚过度引用；使用留出的记忆优势集进行审计。
- **循环中的安全性：** `injection_breach` 必须始终是一个一类、重度惩罚的奖励项——不可信的场景文本是一个数据外泄向量（大脑设计 §10），如果未定价，RL 将找到突破口。
